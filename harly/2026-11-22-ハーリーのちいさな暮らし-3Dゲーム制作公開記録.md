# ハーリーのちいさな暮らし 3Dゲーム制作・公開記録

## 1. この記録の目的

「ハーリーのちいさな暮らし」をアルパカすく〜るラボへ追加し、スマートフォンで遊べる状態まで調整した作業記録である。今後、同じ方向性の縦画面3Dミニゲームを作るときの参考実装・確認手順として使う。

このゲームから再利用したい要点は、3D表現そのものよりも、次の設計順である。

1. 子どもが触る対象と、触った後に起きる変化を先に決める。
2. タイトル画面では3Dを起動せず、開始操作後にWebGLを作る。
3. 3D、物語、時間帯、音、案内表示を一つの状態として管理する。
4. 小さなスマートフォンを基準にUIを作る。
5. ドラッグで屋敷を見回せるようにし、目的物が画面外でも探せるようにする。
6. WebGLが使えない場合と、ブラウザ拡張機能由来のエラーを分けて扱う。
7. GitHub Pagesのbuildとdeployを確認し、実機で最終確認する。

## 3. 中核体験とゲームループ

中核体験は、古い沖縄の古民家を上から眺め、画面内の暮らしの道具や場所をタップすると、ハーリーの行動、時間帯、短い物語が変わることにある。

基本ループは次のとおり。

1. エピソードを選ぶ。
2. メッセージに示された対象を3D空間で探す。
3. 対象をタップする。
4. 物の状態、ハーリーの動き、音、文章が変わる。
5. 朝・昼・夜、または次の場面へ進む。
6. エピソード終了後、次の話、やり直し、話の選択へ移る。

「文章を読むだけ」「正解ボタンを押すだけ」にせず、3D空間のどこを触るかを観察する時間を入れている。

## 4. 現在の実装構造

### 4.1 1画面にまとめた構造

公開物は`harly/index.html`だけで動く。HTML内にスタイル、Reactの実行コード、Three.js系コード、音、ゲーム状態、シーン生成をまとめている。写真や3Dモデルを別ファイルで読み込まず、箱、円柱、球などのプリミティブとCanvasTextureで古民家や道具を組み立てるため、画像・モデルの404が起きにくい。

単体HTMLは配布しやすい一方、現在のファイルはビルド後の圧縮コードを含む。今後テンプレート化するときは、編集用のソースを別に保持し、ビルド結果だけを`index.html`へ出す。圧縮後HTMLを直接編集する方法を通常運用にしない。

### 4.2 画面レイヤー

画面はおおむね次の順で重なる。

- 3D Canvas
- 朝・昼・夜の進行表示
- 音の切り替え
- 話を選ぶボタン
- ラボへ戻るリンク
- 「ドラッグで見まわす」の操作ヒント
- 視点を初期位置へ戻すボタン
- カード表示・メッセージ・操作ヒント
- タイトル画面
- 周辺のビネット表現

CanvasとHTML UIを分けることで、3Dの描画負荷に左右されず、文章とボタンを読みやすくしている。

### 4.3 3Dシーン

シーンは、床、畳、柱、壁、雨戸、布団、ちゃぶ台、テレビ、かめ、かまど、ヒンプン、石垣、くらなどを小さな部品として作り、親グループへ配置する。タップできる対象にはIDを与え、現在の目標IDと一致すると案内マーカーを表示する。

新しいゲームで同じ方式を使う場合は、次の単位に分ける。

- `World`: 背景、床、照明、カメラ
- `Object`: タップできる家具・生きもの・道具
- `Marker`: 次に触る場所の案内
- `Effects`: 時間帯、光、動き、カード演出
- `HUD`: 文章、進行、音、戻る操作

### 4.4 状態管理

最低限、次の状態を一か所で管理する。

| 状態 | 役割 |
|---|---|
| `phase` | タイトル、プレイ中など大きな画面状態 |
| `ep` | 現在のエピソード |
| `step` | エピソード内の進行位置 |
| `target` | 次にタップする3D対象 |
| `tod` | 朝・昼・夜 |
| `busy` | 演出中の多重操作防止 |
| `msg` / `msgKey` | 表示文章と文字送りの更新キー |
| `canAdvance` | 次の時間帯へ進めるか |
| `ended` | エピソード終了状態 |
| `orbit` | 視点の左右回転、上下角度、拡大率 |

タップ処理では、対象IDだけで進めず、`step`、`target`、`busy`を確認する。これにより、連打や別の物の誤タップで物語が飛ぶことを防ぐ。

視点操作はゲーム進行と分けて管理する。1本指またはマウスのドラッグで左右・上下の角度を変え、2本指のピンチまたはホイールで距離を変える。ドラッグ量が一定値を超えたときは、その直後のクリックを無効にし、見回しただけで3D対象を誤タップしないようにする。「視点 ↺」は現在の場面に設定された基準カメラへ戻す。

## 5. 同種の3Dゲームを作る手順

### 手順1: 操作と変化を1文で決める

最初に「何を操作すると、何が、どう変わるか」を1文で書く。

例: 「古民家の道具をタップすると、ハーリーの一日と季節の暮らしが進む。」

この1文に関係しない機能は、最初の試作へ入れない。

### 手順2: 最小の1場面を作る

床、カメラ、照明、タップ対象1個、メッセージ1個だけで試す。対象をタップしたら色、位置、文章、音のうち二つ以上が変わるようにする。操作と結果が分かってから、部屋やエピソードを増やす。

### 手順3: 縦画面を先に固定する

本作は9:16の縦長ステージを中央に置き、幅を`100%`、最大幅を`100vh × 0.5625`としている。文字やボタンにはコンテナクエリ単位`cqw`を使い、ステージ幅に合わせて拡縮する。

確認幅の目安は320px、375px、390px、412px。上部の時刻表示、音、戻る操作が重ならないか、下部メッセージが3D対象を隠しすぎないかを見る。

### 手順4: タイトルではWebGLを起動しない

`phase === "title"`の間はCanvasを描画せず、開始ボタンを押した後に3D Canvasをマウントする。これにより、入口画面はWebGLの成否に関係なく表示でき、ユーザー操作後に音声コンテキストも開始しやすい。

### 手順5: 低負荷の描画設定から始める

本作で安定した設定は次の考え方である。

- アンチエイリアスを無効化する。
- `powerPreference`は`low-power`を使う。
- `failIfMajorPerformanceCaveat`は`false`にする。
- 端末幅に応じてDPRを下げ、最低値を0.5程度にする。
- 影、高密度モデル、大きなテクスチャを最初から増やさない。
- 外部3Dモデルを使う場合は容量、権利、読み込み失敗時の代替表示を決める。

### 手順6: UIはHTMLで重ねる

文章、ボタン、話数選択、ミュート、ラボへ戻る操作はHTMLで作る。3D内テキストだけにすると、小型端末で読みにくく、アクセシビリティ情報も不足しやすい。

上部操作は2段に分ける。1段目にラボ、時刻、音、2段目に話の選択、見回しヒント、視点リセットを置く。安全領域を含めて320px幅から確認し、固定配置のボタン同士が重ならないようにする。

### 手順7: カメラを探す操作にする

目的物を自動で中央へ映すだけでは、3D空間を探索する体験にならない。各場面に基準カメラと注目地点を持たせたうえで、ユーザーのドラッグ量から水平角と垂直角を計算し、注目地点の周囲へカメラを回す。ピンチやホイールでは注目地点との距離を変える。

物語の開始時や重要な対象へ移ったときは基準カメラを更新する。本作の第4話では、かまどを探す段階で台所を注目地点に設定し、最初から対象が画面外になる問題を防いだ。その後は自由に屋敷の周囲を見回せる。

### 手順8: 音は最初の操作後に開始する

iPhoneでは、自動再生される音が制限される。開始ボタンや最初のタップをきっかけにAudioContextを開始する。ミュート状態をUIから切り替えられるようにし、音がなくても進行できる設計にする。

### 手順9: 失敗表示を二段階にする

1. アプリ本体が作れなかった場合は、ページ全体の起動失敗表示を出す。
2. WebGLだけが使えない場合は、Canvas領域内のフォールバックを出す。

アプリ本体の`.stage`が作られた後は、ページ全体のエラー監視で画面を覆わない。iPhoneのブラウザやウォレット機能がページへ追加した`window.ethereum`関連エラーなど、ゲーム外部の例外をゲームの起動失敗と誤判定するためである。

### 手順10: サイトへ戻る動線を必ず付ける

単独ページとして遊べても、ラボ全体へ戻れなければ回遊できない。本作では「← ラボ」または共通の「← ラボ一覧」からラボトップへ戻る。タイトル画面とプレイ中の両方で表示する。

### 手順11: ビルド結果と編集用ソースを分ける

将来の推奨構成は次のようにする。

```text
game-project/
├── src/                 # React・3D・状態・音の編集用ソース
├── package.json         # 依存バージョンを固定
├── package-lock.json    # 再現可能なビルド
├── tests/               # 状態遷移などの必要なテスト
└── dist/index.html      # GitHub Pagesへ置く単体HTML
```

ラボ側には公開用`<game-name>/index.html`と作業記録を置く。編集用ソースを同じリポジトリへ置く場合も、どちらが正本かをREADMEで明記する。

## 6. 今回発生した問題と対処

| 症状 | 原因・判断 | 対処 |
|---|---|---|
| Braveで開始後に`Error creating WebGL context` | 高性能GPUを優先したWebGL生成が環境に合わない | `antialias: false`、`powerPreference: low-power`、性能制限時も失敗扱いにしない設定へ変更 |
| 入口画面が一瞬見えて消える | タイトル表示と同時にCanvasを作り、WebGL失敗が全体へ影響 | タイトル中はCanvasを作らず、開始後にマウント |
| 起動失敗時に理由が分からない | フォールバック表示が不足 | ページ全体とCanvas内の二段階フォールバックを追加 |
| iPhoneで`Script error.` | 内容のない汎用エラーを致命的エラーとして表示 | アプリ本体が起動済みなら汎用エラーで全体を覆わない |
| iPhoneで`window.ethereum.selectedAddress` | ウォレット機能が注入したゲーム外のコードの例外 | ゲーム本体起動後の外部例外をページ全体の起動失敗として扱わない |
| ラボへ戻れない | ゲーム内にサイトナビゲーションがなかった | タイトル・プレイ画面共通の「← ラボ」を追加 |
| 第4話で「かまどをタップ」と出ても、かまどが見えない | 場面のカメラが台所を向いていなかった | かまど段階の注目地点を台所へ切り替え、対象と案内マーカーを画面内へ入れた |
| 屋敷の裏側や周囲を見られない | 場面ごとの固定カメラだけだった | 1本指・マウスのドラッグ回転、2本指ピンチ・ホイールの拡大縮小、視点リセットを追加 |
| 見回し操作中に対象が反応する | ドラッグ終了時のクリックが対象へ伝わる | 移動量を判定し、ドラッグ後のクリックを抑止 |
| 「はなし」「ドラッグで見まわす」「視点」が上段へ重なる | すべての操作を同じ高さへ固定していた | 時刻・音などを上段、見回し関連を下段に分け、`14cqw`位置へそろえた |

## 7. テスト記録

- HTML内のJavaScriptを`node --check`で構文確認。
- ローカル配信でタイトル画面を表示。

- 第4話を「かまどをタップ」まで進め、台所とかまどの案内マーカーが表示され、かまどをタップして次へ進めることを確認。
- 上部操作を2段に分け、「はなし」「ドラッグで見まわす」「視点」が時刻・音の操作と重ならないことを405px相当の縦画面で目視確認。

## 8. セキュリティ・データ確認

本作は公開静的ゲームで、ログイン、API、データベース、フォーム、ファイルアップロード、児童生徒情報の入力・保存を持たない。`localStorage`も使用していない。

公開HTMLに`window.ethereum`、`selectedAddress`、秘密鍵形式、代表的なGitHub/OpenAIトークン形式が含まれないことを静的確認した。外部通信としてGoogle Fontsを参照する。ゲーム進行にフォント取得は必須ではない。

今後、得点保存、名前入力、学習履歴、AI連携、外部APIを追加する場合は、この静的ゲームと同じ安全性とはみなさず、個人情報、認証・認可、外部送信、ログ、入力検証を別途設計・確認する。

## 10. GitHub Pagesへ公開する手順

1. `alpaca-school/lab`の`main`を最新にする。
2. ルートと対象フォルダの`README.md`、`AGENTS.md`、`CLAUDE.md`を確認する。
3. 公開用フォルダを`<repo>/<game-name>/`へ置き、入口を`index.html`にする。
4. ラボトップに作品一覧がある場合は、既存形式でカードを追加する。
5. ローカルサーバーでタイトル、開始、主要操作、戻るリンクを確認する。
6. `git status`と`git diff --stat`で対象外ファイルが変わっていないことを確認する。
7. 変更対象だけをコミットし、`main`へ通常pushする。force pushは使わない。
8. GitHub Actionsでbuild、deploy、report-build-statusを別々に確認する。
9. 公開URLをキャッシュ回避用クエリ付きで開き、新版を確認する。
10. Brave、iPhone、可能ならAndroid実機で開始後の3D表示を確認する。

## 12. 正本と更新方針

- 現在の公開正本は`alpaca-school/lab`の`main`にある`harly/index.html`。
- この記録は現在の実装から抽出した制作・公開ノートであり、ゲームコードそのものの代わりではない。
- 次回テンプレートを作るときは、圧縮済みHTMLを複製するだけでなく、編集用ソース、依存バージョン、ビルド手順、テスト手順を一緒に残す。
- 地域文化や学習内容を変更する場合は、根拠資料と現在方針を再確認する。
- 子どもの入力や学習履歴を扱う機能を追加する場合は、公開静的ゲームの範囲を超えるため、別のセキュリティ設計を行う。
