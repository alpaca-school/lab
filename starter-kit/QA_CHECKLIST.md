# アルパカすく〜るラボ Starter Kit｜QA_CHECKLIST

基準：Obsidian「アルパカすく〜るラボ ゲーム制作・公開標準 第2版」

## A. 代表3画面を先に合格させる

- [ ] 体験・操作画面
- [ ] 長文結果画面
- [ ] 最終3〜4ボタン画面

この3画面が合格する前に全ステージへ横展開しない。

## B. スマホ可視領域

最低限の回帰条件：

- [ ] 390 × 560
- [ ] 390 × 650
- [ ] 390 × 760
- [ ] iPhone実機
- [ ] Safari系ブラウザUI表示中
- [ ] 画面回転後
- [ ] ピンチズーム後に操作不能にならない

確認：

- [ ] Safe Areaへ食い込まない
- [ ] 必須ボタンが下部ブラウザUIへ隠れない
- [ ] Visual Viewport同期で画面が暴れない
- [ ] 横スクロールが発生しない

## C. 操作

- [ ] タッチ対象が原則44×44 CSS px以上
- [ ] 次に押す対象が見える
- [ ] 最後の対象まで押せる
- [ ] 説明文と操作UIが重ならない
- [ ] 連打で状態が壊れない
- [ ] やり直し・戻るが機能する

## D. 日本語・ルビ

- [ ] 送り仮名が不自然に分断されない
- [ ] 1〜2文字だけの孤立行が連続しない
- [ ] 右側に大きな空白が連続しない
- [ ] ルビが親文字から離れない
- [ ] 長文に `text-wrap: pretty` を使っていない
- [ ] BudouX失敗時も本文は読める
- [ ] 文字を小さくする前に余白・行間・構造を確認した

## E. ナビ

### 1〜2ボタン
- [ ] 下部予約領域に収まる
- [ ] 本文に押し出されない

### 最終3〜4ボタン
- [ ] 2×2等で整理されている
- [ ] 本文・出典カードとの上余白がある
- [ ] ボタン間gapがある
- [ ] 下部Safe Areaとの余白がある
- [ ] sticky固定で本文に被っていない

## F. 音・動き

- [ ] 音ON/OFFがある、または音を使わない理由が明確
- [ ] 音が鳴らなくても進行可能
- [ ] 操作→動き→結果→音のタイミングが一致
- [ ] `prefers-reduced-motion` を妨げない

## G. 教材内容

- [ ] 学習目標と操作が対応している
- [ ] 史実と創作を分けている
- [ ] 未確認事項を推測で補っていない
- [ ] 出典・参考文献を実際に使った資料だけ記載
- [ ] 外部素材の権利・ライセンスを確認した

## H. Security Gate

静的教材でも最低限：

- [ ] APIキー・Token・秘密情報がない
- [ ] 個人情報・児童生徒情報を含まない
- [ ] 外部入力を追加した場合は検証・エスケープを確認
- [ ] 新規依存ライブラリの必要性・バージョンを確認
- [ ] Critical / Highの未解決問題がない

## M. 物語・タイトル・UI衝突

物語性のあるゲーム：
- [ ] 物語本文の漢字に対象年齢に応じたルビがある
- [ ] モーダルは「見出し／本文スクロール／下部ナビ」の3層で、本文量が増えても操作ボタンが押し出されない
- [ ] Safari等のブラウザUI表示中でも「次へ／閉じる」がVisual Viewport内に完全表示される
- [ ] 前作の正本設定と今回の創作を区別した
- [ ] 初回物語を後から再読できる
- [ ] 長い物語を1画面へ詰め込みすぎていない
- [ ] 物語を読まなくてもゲーム開始を選べる

タイトル画面：
- [ ] タイトルと操作群の間に十分な余白がある
- [ ] 主操作・副操作の階層が見た目で分かる
- [ ] 低いiPhoneでボタン群が上へ詰まりすぎない
- [ ] 色・角丸・影・モチーフがゲーム世界観と一貫している

固定UI：
- [ ] 上部ステータスと下部案内を役割分離した
- [ ] ホーム等の低頻度ナビが案内・操作を邪魔しない
- [ ] ホーム等の浮動UIを「左下固定」等の位置決めだけで済ませず、主操作と重なる画面では安全な候補位置へ退避する
- [ ] 浮動UIの候補位置はVisual Viewport内かつ主要blockerと非衝突である
- [ ] 進捗とHUDボタンが重ならない
- [ ] 下部案内とカード／ナビが重ならない
- [ ] 必要な画面では実座標の衝突検査を使った
- [ ] 自動衝突検査後もiPhone実機スクリーンショットで確認した

保守性：
- [ ] 巨大な単一HTMLを無理に正本化していない
- [ ] ファイル本文を取得できない状態で上書きしていない


## N. 操作領域・自動回帰・検証版分離

- [ ] 必須操作の存在・表示を明示的に検査した
- [ ] CSS zoom・transform適用後の実測で操作領域44×44 CSS px以上
- [ ] ボタン本体の無限拡大縮小・移動がない
- [ ] 狭い画面では余白・装飾・配置・画面分割を優先した
- [ ] Visual Viewport内に収まり、対象同士の交差・中心タッチ妨害がない
- [ ] 390×560 / 390×650 / 390×760 / 1280×800で回帰テスト
- [ ] 強制クリックやテスト基準の緩和で合格させていない
- [ ] 監視の自己再発火・重複登録・画面離脱後のタイマー残留がない
- [ ] 練習モードが本編の保存を汚さない（該当時）
- [ ] 検証版は本番と別URL・保存キー・依存バージョンを使用
- [ ] 検証中表示・一覧非掲載・noindex（認可とは別）を確認
- [ ] 自動QAの対象・結果・コミット・実行URL・画像を記録
- [ ] 実機の端末・OS・ブラウザ/PWA・確認結果を記録（未取得は明示）
- [ ] 代表ステージの自動QA・実機QA合格後に横展開
- [ ] 3Dの実タッチ・音・読み上げ・Safari UIは実機でも確認


## O. 第39章の進行ゲート（検証候補）

下位ゲート不合格の場合、後続合格・正式採用を宣言しない。

- [ ] G0：正本、編集ソース、受入条件、非変更範囲、復旧方法を確認
- [ ] G1：構文、設定、依存・バージョン・ロックを確認
- [ ] G2：正例・負例・境界例、検査関数自身、独立した期待値
- [ ] G3：実DOM形式、ルビ、44px、対象ゼロ、衝突、最小画面
- [ ] G4：機能・地点別独立検査、代表／最悪条件、通し回帰
- [ ] G5：独立レビュー、Security Gate、教材内容、権利
- [ ] G6：実機、公開承認、Pagesと公開URLの証跡

不合格時はrun ID、commit、期待値、実測、原因分類、最小再現を記録する。ローカル未検証を明示し、CI代替は検証ブランチに限定する。Starter Kit自身の単体・部品・回帰と独立レビューを完了するまで候補をmainへ昇格しない。
